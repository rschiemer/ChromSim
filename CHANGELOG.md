# Changelog

All notable changes to ChromSim are documented here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added
- Real-data support and case studies (2026-11-27):
  - `unicorn_res` importer: native UNICORN 3–5 result files (`.res`) from ÄKTA prime/purifier/
    explorer, written from the published layout (no new dependency); units and scale factors are
    read from each curve, plus fractions, injection marks and logbook. Synthetic `.res` fixture
    (`tests/data/unicorn_res/`) generated by `generate_fixtures.py`.
  - `akta_xls` importer: UNICORN legacy Excel 97–2003 exports (`.xls`), via the new dependency
    `xlrd` (ADR 0012). Fixture converted from the synthetic `.xlsx` with LibreOffice.
  - UNICORN unit spellings (`%B`, `mAu`, `ml/min`, leading spaces) are normalised by all UNICORN
    importers, so `%B` becomes a fraction and flow an SI flow rate.
  - `generic_csv`: files without header (`header: false`, columns by 0-based position),
    `delimiter: whitespace`, `.dat` files. New `generic_xlsx` importer for Excel tables with the
    same mapping.
  - Concentration signals (`mM`, `g/L`, …) are converted to mol/m³ / kg/m³ and classified as
    `concentration` (or `salt`); `SignalTarget(..., component=...)` fits a measured component
    concentration.
  - `time_to_volume` (time-axis data at constant flow) and `inlet_profile` (the method's inlet
    salt, shifted by a delay volume: outlet salt for the Yamamoto method without conductivity).
  - `examples/case_studies/`: `fetch_data.py` (pinned, checksummed downloads of public data),
    case study 01 (14 real UNICORN files in four formats), 02 (full calibration on measured lysozyme/SCX data
    from Fraunhofer IME), 03 (Yamamoto cross-check against CADET-Process). Slow tests run them
    when the data are present.
  - Docs: "Case studies on published data", importer sections, ADR 0011 (third-party data),
    ADR 0012 (xlrd).
- Phase 7 web UI and server-ready plumbing (SPEC §8, §8.1):
  - `FileStorage` workspace folder: projects (YAML), write-once read-only data files, results
    and optimization histories (HDF5), JSON records; `created_by`/`created_at` on everything.
  - `LocalProcessRunner` (`JobRunner` protocol: `submit`, `status`, `cancel`, `result`,
    `list_jobs`): jobs in worker processes, status and cancel requests stored in the workspace
    so they survive a browser refresh; `JobCancelled`, `JobError`.
  - `Workspace`: per-session object with `submit_simulation`, `submit_fit(FitSetup)`,
    `submit_process_optimization(ProcessSetup)`, `job`, `result`, `cancel`, `jobs`.
  - `codegen`: complete Python scripts for what each page does ("Show Python code").
  - NiceGUI pages Project, Data, Simulate, Calibrate (tracer, Yamamoto, inverse fit), Optimize,
    Results; forms generated from the pydantic models with unit selectors; `chromsim ui`
    (`--workspace`, `--port`, `--native`, `--no-browser`) and `pixi run ui`; a clear message
    if NiceGUI is not installed.
  - Helpers used by the UI and usable from Python: `project_from_dict`, `unit_choices`,
    `field_dimensions`, `isotherm_parameter_table`, `fit_parameter_candidates`,
    `process_variable_candidates`, `tracer_run_from_file`, `tracer_summary`,
    `lge_run_from_file`, `plot_correlation_matrix`.
  - Tests: page smoke tests and a U1–U6 walkthrough in the UI (NiceGUI simulated user), page ↔
    tutorial parity, no module-level mutable state, storage/jobs, codegen, helpers.
  - Tutorial 05 (`examples/05_results_and_workspace.py`): workspaces, background jobs, stored
    results.
- Docs: "Web UI, workspaces and jobs", ADR 0003 (NiceGUI).
- Phase 6 process analysis and optimization:
  - Pools and KPIs (`Pool`, `pool_performance`): recovery, purity (by mass when molecular
    weights are known), productivity per packed-bed volume, specific buffer consumption, pool
    concentration; `fed_amounts`, `default_impurities`.
  - `optimal_pool`: exact maximum-recovery cut points at a required purity, optionally restricted
    to method steps (`pool_steps`).
  - `optimize_process`: method variables by project path, nested exact cut points, one or
    several objectives (Pareto front via NSGA-II), purity constraint, parallel option.
  - `plot_chromatogram(..., pools=...)`, `plot_pareto`.
  - Parity test against CADET-Process's Fractionator (~3e-7 relative); unit, workflow and
    plotting tests.
  - Tutorial 04 (`examples/04_optimize_process.py`): 77 % → 94 % recovery at 99 % purity, and the
    recovery–productivity Pareto front.
- Docs: "Fractionation and process optimization", ADR 0010 (fractionation; SPEC §7.4 note).

### Changed
- `akta_csv` strips UNICORN 5 curve prefixes (`<result name>:<n>_UV` → `UV`).
- The importer-registry test compares with the registry before the rejected registration instead
  of a hard-coded list (same check, robust to new importers).
- Code review and simplification (ponytail review, 2026-11-27):
  - `asymmetry_factor(..., window=)` restricts the peak search to a range, like `peak_moments`.
  - `FitSetup.expected_evaluations()`; fit progress bars count every multi-start.
  - `plot_correlation` reuses `plot_correlation_matrix`; `FileStorage` checks for missing files
    in one place; `api.check_discretisation` is the checks function itself (no wrapper).
  - `akta_xlsx` recognises a file from its first rows instead of reading the whole workbook.
  - Removed the unused `Signal.shifted`.
- Module-level constant tables are read-only (`MappingProxyType`, `frozenset`, tuples); the HIC
  parameter tables moved into the isotherm class.
- Nelder–Mead starts from a simplex of 10 % of each scaled range (`initial_step`), so objectives
  that are flat at small scales don't stop it at once.
- `units.from_si` accepts arrays; `get_value` reads quantities in CV and pH.
- Phase 5 plugins:
  - CADET-native isotherms GIEX (salt + pH), MPM Langmuir, HIC constant water activity, HIC
    water on hydrophobic surfaces, Bi-Langmuir; pH pseudo-concentration unit `pH`;
    `isotherm.global_parameters`.
  - Python isotherms (`PythonIsotherm.flux`) and the worked example `MixedModeLangmuir`.
  - Reference backend (LRM/LRMP, mixer, tubing) in numpy/scipy; ≤ 1 % NRMSE against CADET.
  - Optimizer interface (SPEC §6) with registry and adapters `least_squares`, `nelder_mead`,
    `lbfgsb`, `differential_evolution`, `nsga2`, `unsga3`; scaled space, history, callbacks,
    caching and parallel batch evaluation; `api.optimize`.
  - `inverse_fit(..., optimizer=, parallel=)` on the optimizer interface.
  - HDF5 result files with provenance: `write/read_simulation_result`,
    `write/read_optimization_result` (full evaluation history).
  - Contract tests auto-applied to every registered isotherm and optimizer; exact isotherm
    equivalence tests; reference-vs-CADET benchmark.
- Docs: theory pages for all new isotherms, how-tos "Add an isotherm" and "Add an optimizer",
  ADR 0008 (reference backend, route to production), ADR 0009 (optimizer interface).
- Phase 4 calibration:
  - Peak analysis (`analysis/peaks.py`): moments with injection correction, plate number, HETP,
    asymmetry factor, sub-grid peak maximum.
  - Tracer workflow: system volume, ε_c, ε_t, ε_p from first moments; D_ax via the closed–closed
    dispersion model, flagged when system-dominated; `apply_to(project)`.
  - Yamamoto method derived for ChromSim's model (validated against CADET to < 1 %); helpers for
    gradient slope and delay-corrected elution salt; `plot_yamamoto`.
  - Inverse fit: `FitParameter` (project paths, lin/log scaling, shared or per-experiment),
    `SignalTarget`/`AssayTarget` with a residual registry (normalized, absolute, sd_weighted with
    LOQ censoring), multi-experiment TRF least squares with multi-start and progress callback.
  - Uncertainty: linearised covariance, 95 % intervals, correlation matrix, flags for high
    correlation and bounds; `plot_correlation`.
  - Synthetic-data recovery tests (tracer, Yamamoto, multi-experiment fit with noise).
  - Calibration fixtures (tracer pulses, four LGE runs) and Tutorial 03.
- Docs: "Calibrating a model", Yamamoto derivation, ADR 0007 (calibration conventions).

### Fixed
- `inverse_fit` with an optimizer that returns no Jacobian (e.g. `nelder_mead`) and
  `parallel > 1` left the worker processes of the final Jacobian running.
- Tracer asymmetry factors use the run's `window`, like the moments; a larger peak outside the
  window was measured instead.
- `read_assay` reports blank or unreadable fraction start/end volumes instead of storing NaN
  volumes (silent NaN comparisons) or failing with a bare `ValueError`.
- `plot_overlay` axis titles list only the signals that are drawn.
- `test_no_module_state` compares module paths with "/" so the allow-list also matches on
  Windows (the check itself is unchanged).
- Web UI: saving a project under an invalid name, or applying a tracer analysis that does not fit
  the system volumes, shows the error instead of raising an unhandled exception.
- Text assigned into nested dicts of a project (e.g. `step.inlet["mAb"] = "1 g/L"`) no longer
  crashes unit conversion.
- `compare_with_assay(..., warn=False)` to avoid repeated mismatch warnings during fits.
- Phase 3 experimental data:
  - `Experiment`, `Signal`, `Fraction`: imported runs in SI units, each signal on its own axis,
    fraction marks, injections, run log and provenance (incl. SHA-256 of the raw file).
  - Importer registry with `akta_csv` (UNICORN text: UTF-16/UTF-8, tab/comma/semicolon,
    decimal commas), `akta_xlsx` and `generic_csv` (column mapping); `read_chromatogram` picks
    the importer automatically. Shared importer contract tests.
  - `FractionAssay` + YAML mapping profiles (wide/long, CSV/XLSX, LOQ flags, readouts as sums of
    components); `read_assay`.
  - Preprocessing: baseline subtraction (constant/linear), UV → concentration (Lambert–Beer),
    `ConductivityCalibration` and conductivity → salt, resampling, volume → time.
  - `predict_uv`, `predict_conductivity` (with detector delay volumes); `fraction_averages`,
    `compare_with_assay` (mismatched fraction ids reported, never guessed); `plot_overlay`,
    `plot_fraction_comparison`.
  - Synthetic, realistically formatted fixtures and their generator (`tests/data/`); end-to-end
    test that the generating parameters reproduce all data within noise.
- Example project `cex_mab_hmw_lge.yaml` (mAb + HMW), NaCl conductivity calibration, two assay
  mapping profiles, Tutorial 02 (`examples/02_compare_with_data.py`).
- Docs: "Experimental data", how-to "Add a chromatogram importer", ADR 0006 (openpyxl).
- Dependency: openpyxl.
- Phase 2 CADET backend:
  - Isotherm descriptors `Linear`, `Langmuir`, `SMA` with a registry (`register_isotherm`,
    `get_isotherm`, `list_isotherms`), parameter checks (unknown/missing/out of bounds, salt as
    component 0, ionic capacity for SMA) at project load, and theory pages.
  - `CadetBackend`: Project → CADET-Process flow sheet (mixer, tubing, LRM/LRMP/GRM column) →
    CADET-Core; method steps as events with linear gradients; clear errors listing missing
    transport parameters.
  - `SimulationResult` with time, volume and CV axes, outlet in any concentration unit, and
    provenance (project YAML, versions, solver settings, time, user).
  - `api.simulate`, `api.check_discretisation`, `api.plot_chromatogram`.
  - `System.tubing_diameter` and `System.tubing_axial_dispersion` (optional, with defaults).
  - Physics tests: tracer first moments (LRM/LRMP/GRM), system dead-volume delay, gradient delay,
    linear-isotherm first moment, Langmuir breakthrough plateau and stoichiometric time, mass
    balances including SMA gradient elution.
- Tutorial 01 (`examples/01_simulate_lge.py`) simulates the SPEC §4.3 project.
- Docs: "Simulating a project", isotherm theory pages, ADR 0005 (CADET backend conventions).
- Phase 1 domain model:
  - `chromsim.units`: the single unit-conversion module (pint). `Quantity` keeps the user's unit
    text for lossless files; conversions to SI for lengths, volumes, durations (time, volume or
    CV), flows (cm/h ↔ mL/min), concentrations (mM, g/L with molecular weight), diffusivities;
    column cross-section and volume.
  - `chromsim.core`: `Component`, `Column`/`ColumnModel`, `Resin`, `System`, `Step`,
    `IsothermConfig`, `SolverSettings`, `Project`, with cross-checks (unique component names,
    known components in inlets/isotherm/transport, molecular weight for g/L), and
    `resolve_method()` turning a method into an SI timeline.
  - `chromsim.io.project_file`: YAML ⇄ `Project` (`load_project`, `save_project`,
    `project_from_yaml`, `project_to_yaml`) with `schema_version` migrations and readable,
    located error messages (`ProjectFileError`).
  - New errors `UnitError` and `ProjectFileError`; all of the above exported from `chromsim.api`.
- Example project `examples/projects/cex_mab_lge.yaml` (SPEC §4.3) and notebook
  `examples/00_project_files_and_units.py`.
- Docs: user guide "Project files and units"; ADR 0004 (units policy).

### Fixed
- `chromsim doctor` no longer creates a `tmp/` folder in the current directory or changes
  Python's global temp directory (CADET-Process default); CADET now runs in its own temporary
  folder.
- Phase 0 scaffold: package layout from SPEC §4.1, pixi environment (`default` and `noui`) with
  lockfile and exported `environment.yml`, pre-commit hooks, GitHub Actions CI (lint, tests on
  Linux/macOS/Windows, no-GUI tier, docs build), MkDocs site skeleton.
- `chromsim doctor` / `chromsim.api.doctor()`: reports the Python, ChromSim, CADET-Process,
  CADET-Python and CADET-Core versions and runs a sub-second CADET tracer-pulse simulation checked
  for mass balance.
- `ChromSimError` / `EnvironmentCheckError` exception hierarchy.
- Tests pinning the CADET-Process names used by `doctor`, and a static check that `chromsim.ui`
  imports only `chromsim.api`.
- ADR 0001 (CADET-Process as process layer) and ADR 0002 (pixi).
- Example `examples/00_environment_check.py`.
