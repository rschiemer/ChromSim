# 0002 — pixi for environment management

- Status: accepted
- Date: 2026-10-10

## Context
CADET-Core is a compiled C++ program whose binaries come from conda-forge. CADET-Process and one
of its dependencies (`hopsy`) are only on PyPI. Maintainers need one command that installs the
same environment on Linux, macOS and Windows, and CI needs a lockfile to be reproducible.

## Decision
Use [pixi](https://pixi.sh) with `pixi.toml` and a committed `pixi.lock`.

- conda-forge packages for Python, CADET-Core and the scientific stack; PyPI packages
  (`pypi-dependencies`) for CADET-Process and ChromSim itself (editable).
- Environments: `default` (everything, including the optional NiceGUI UI) and `noui` (test tools
  only, no NiceGUI), which runs the "no-gui" test tier from SPEC §9. Both share one solve group,
  so they have identical package versions.
- `environment.yml` is exported with `pixi workspace export conda-environment` as a fallback for
  people without pixi.
- Build backend for `pyproject.toml`: hatchling. It is only needed when building or installing
  ChromSim, not at runtime.

## Notes from setting up the environment
- `cadet-python` comes from PyPI, through CADET-Process, not from conda-forge. The conda-forge
  build pulls in `addict 2.4`, but CADET-Process pins `addict==2.3`, so the solve fails.
- osx-arm64 is declared with `macos = "14.0"`. hopsy only publishes macOS arm64 wheels for
  macOS ≥ 14; without this setting pixi picks the source distribution, which needs a C++
  toolchain to build. Intel Macs (osx-64) are not supported.

## Approved additions beyond the SPEC §3 list (2026-10-10)
- `hatchling`: build backend only, not needed at runtime.
- `pymdown-extensions <12`: an upper limit on an existing docs dependency, not a new package.
- `pytest-cov`: already named in SPEC §3; listed here for completeness.

## Consequences
- One-command setup (`pixi install`) and identical environments locally and in CI.
- Maintainers have to learn a few pixi commands (`install`, `run`, `add`). They are listed in
  CLAUDE.md.
- Dependency changes go through `pixi.toml` and need an ADR (CLAUDE.md rule 5).
