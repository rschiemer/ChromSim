# 0011 — Third-party data: fetched, never committed

- Status: proposed (2026-11-27)
- Date: 2026-11-27

## Context
ChromSim's importers and calibration workflows were developed against synthetic data. Real
chromatograms published by other groups (UNICORN files on GitHub, measured calibration data
shipped with CADET-MCMC and the CADET-Workshop) test them far better. Their licenses differ:
MIT, GPL-2.0, CC BY-NC-SA 4.0 (non-commercial, share-alike) and in one case none at all.
ChromSim's repository is marked "internal use only" in `pyproject.toml` but is hosted publicly,
so copying such files into it would redistribute them under terms that conflict with their
licenses.

## Decision
- No third-party data in the repository. `examples/case_studies/fetch_data.py` downloads each
  file from a **pinned commit** of its public repository, checks its **SHA-256**, records the
  license next to the data, and stores it in the git-ignored `examples/case_studies/data/`.
- Test fixtures stay synthetic and generated by `tests/data/generate_fixtures.py` (e.g. the
  native `.res` fixture re-encodes our own synthetic run in the UNICORN 5 layout).
- Tests that need third-party data skip themselves when it has not been fetched; the slow
  case-study tests run them end to end when it has.
- The `.res` importer is written from the published layout description, not from PyCORN's
  code (GPL-2.0), and adds no dependency.

## Consequences
- Fresh clones and CI run without the third-party data; run `fetch_data.py` to include the
  real-data checks (needs access to raw.githubusercontent.com).
- If an upstream repository disappears, its case study can no longer be reproduced; the
  checksums make a replacement copy verifiable.
- Legacy `.xls` UNICORN exports remain unsupported (ADR 0006); one public data set
  (fplc-chromatogram) uses that format and is therefore not part of the case studies.
